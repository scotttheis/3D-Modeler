RB-03: Python-reference actions beside Rust

Each Python image was captured from the visible reference app during the named operation. Rust captures are beside them for review. Both clients were 1280 × 840 px at 96 DPI / 100% display scale. Click an image to open its original capture.

Review status: captures were inspected and the observed differences are recorded; owner visual acceptance is still pending. Some pairs use different recent-list contents or accumulated scene state; each note calls that out. These are interaction records, not a pixel-difference score.

Welcome and recents

Light recent cards

The Python reference uses two-column cards with large wireframe model thumbnails and scrolling; this capture shows only the upper portion. Rust uses four compact columns with a status label and Open button, showing more entries at once. The nine paths/order are not identical in these captures, so treat this as a layout/preview comparison, not a pixel-matched ordering check.

Dark recent cards

The same visible difference appears in Dark. The old app retains the wireframe preview style; Rust shows compact shaded preview tiles with file status and Open actions.

Lifecycle

New on a dirty scene: prompt

The old app puts a native Save Changes dialog over the current viewport, with Save, Discard, and Cancel. Rust shows its own centered Unsaved changes dialog. Both keep the current scene visible behind the prompt.

Cancel New and keep the scene

The Python capture was taken after Cancel returned to the same dirty scene. Rust has the same action result; object counts and camera framing differ because the two app sessions used different preceding scene edits.

Discard and complete New

The old app returns to its empty scene after Discard. Rust also completes New and clears the dirty marker.

Save As surface

The old app opens the Windows Save Project file picker, with the .3dp filter and standard filename controls. Rust opens an in-app Save Project form with a path field and Browse button. Themes differ in these existing captures.

Saved project plus OBJ and PLY imports

Both screens show python-current.3dp with two additive model imports; the selected PLY reports 2 × 3 × 4 mm. This is the closest same-project, same-import-state scene pair.

Import

Add/Open model picker

The old app presents the Windows Add 3D Model picker and its supported-format filter. Rust presents an in-app Import Model form with a unit selector and Browse action. This is a direct visible workflow difference.

Import units

Unitless STL in millimetres

Both show the unitless box as 2 × 3 × 4 mm after the mm import. The Python app places numeric values in its lower Resize strip; Rust shows them in the right Transform panel.

Unitless STL in inches

The old app displays the converted 50.8 × 76.2 × 101.6 mm dimensions after importing with inches. Rust reports the same dimensions; its capture includes an earlier scene object.

Import

Two-object 3MF result

The Python screen shows the two named 3MF parts after import. Rust shows the same two names after framing. Selection and starting-scene state differ, so geometry color and framing should be reviewed directly rather than inferred from these images.

Two-object glTF result

The Python screen shows the two glTF parts and their imported scene. Rust shows the imported parts with the first part selected; its capture includes two earlier box objects.

Two-object GLB result

The Python screen shows the two GLB parts. Rust shows the same two imported parts with the second selected.

Import cancellation and errors

Cancel the model picker

Both captures return to the scene after cancel. The Python picker is a Windows dialog; Rust uses its own import flow and returns without adding geometry.

Malformed STL

The old app leaves the existing scene and reports “Import contained no objects” in the status line. Rust keeps the scene and presents a detailed in-form parse error. This is an observed error-message and presentation difference.

Export

Export with no selection: completed 3MF

Both complete a no-selection 3MF export. The old app reports completion in its status line after the native Save dialog; Rust reports the written path in its status line.

Export destination picker/form

The old app uses the Windows Export Mesh dialog with 3MF as the default filter. Rust uses a centered Export form with a path field and Browse button.

Overwrite confirmation

The old app nests a Confirm Save As Yes/No prompt over the Windows picker. Rust shows a Confirm overwrite form with Overwrite and Cancel. Both offer a non-destructive cancel choice.

Overwrite cancelled

Both captures show the existing destination preserved after cancellation; the Python output hash was unchanged.

One object selected for export

Both scenes show one selected object before export. The Python capture reflects its reference selection state; Rust captures the selected-visible export route.

Cancel the export picker

Both return to the same visible scene after cancelling the destination picker, with no output path committed.

Recent dispatch

Open a model from Recents

Each app opens a model recent through the additive model-import path; the Python image shows the resulting imported object.

Recent failures

Missing recent entry

The old app shows a File Not Found dialog with the path, then removes the row after dismissal. Rust renders a Missing row with a Remove action and does not use a modal warning.

Corrupt .3dp recent

The Python app shows an Open Error dialog, then keeps the current scene. Rust leaves the corrupt entry visible and puts the invalid-project reason in the welcome status line; the scene remains unchanged.

WRL recent import

The old app shows an Import Error dialog because WRL is not an import format, then reports the reason in the status line. Rust keeps the entry visible and reports the unsupported format in its status line.

Lifecycle

Exit a dirty scene

Both show a Save/Discard/Cancel guard before exit. The Python app uses the native Save Changes dialog; Rust uses its custom Unsaved changes panel.
