# R2c GLTF/GLB evidence

## Scope

R2c ports the Python `src/gltf_io.py` boundary without changing
`L:\Builder3D`. The Rust core now owns bounded glTF 2.0 and GLB 2.0 parsing
and export, with metres converted to the 3D Modeler millimetre model boundary.

Implemented behavior includes:

- JSON `.gltf` and binary `.glb` containers with checked headers, chunk sizes,
  JSON/BIN placement, and declared buffer lengths;
- embedded base64/percent-encoded resources and safe external buffers below an
  approved document directory;
- bounded buffers, buffer views, accessors, sparse accessors, normalized
  component decoding, index validation, and TRIANGLES/STRIP/FAN conversion;
- scene selection, node hierarchy traversal, cycle/depth limits, matrix and
  TRS transforms, mesh names, materials, PBR base colors, and representative
  vertex colors;
- validated normals on input and generated finite vertex normals on export;
- self-contained JSON export, one-sidecar path export with atomic replacement,
  GLB export, round trips, and the single-mesh `MeshFormat` bridge.

## Python golden comparison

`tests/fixtures/gltf/python_reference.gltf` and its four `.b64` buffer members
were generated by the Python `src.gltf_io.save_gltf` implementation using two
translated colored boxes. Rust loaded the unchanged Python document and
matched these semantic results:

| Item | Extents (mm) | Translation (mm) | RGBA |
|---|---:|---:|---:|
| First part | 10, 20, 30 | 4, 5, 6 | 0.2, 0.4, 0.8, 128/255 |
| Second part | 2, 3, 4 | -2, 1, 3 | 1, 0, 0, 1 |

The fixture also exercises Python's external buffer naming and shared normal
accessor. The Rust exporter was reopened through the same Rust importer for
both embedded `.gltf` and `.glb` output; the GLB declared length matched the
complete byte stream and exported primitives contained POSITION and NORMAL
attributes, PBR colors, and alpha mode selection.

## Limits and intentional boundaries

The parser is geometry/material focused like the current 3D Modeler import
boundary. Animations, skins, morph targets, textures/UV sampling, and vendor
extensions are not represented in `GltfItem`; unsupported primitive modes are
rejected with `CoreError::Gltf`. The exporter emits a single binary buffer,
generated normals, and validated PBR base colors rather than reproducing
trimesh's internal accessor ordering byte-for-byte.
